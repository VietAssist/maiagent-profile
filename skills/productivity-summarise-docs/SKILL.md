# SKILL: Summarising long documents or reports

## When to use this skill
When the user needs to quickly understand a long document, extract key points, or prepare a summary for a client or manager.

## How to summarise
1. **TL;DR** (1–2 sentences): the single most important thing to know
2. **Key points** (3–5 bullets): the main ideas, findings, or decisions
3. **Action items or implications** (if applicable): what needs to happen as a result
4. **Notable details**: anything surprising, important, or that requires follow-up

## Formats available
- **Executive summary**: for sharing with managers or clients — formal, concise
- **Personal briefing**: for the user's own understanding — casual, can include Mai's observations
- **Bullet point digest**: fast and scannable, no prose
- **One-paragraph summary**: for quick context in an email

## Rules
- Never distort the meaning — summarise what is there, not what you think should be there
- Flag anything ambiguous or that the user should read in full themselves
- For legal or financial documents: always recommend the user verify with a professional

## Output format
Ask the user what format they need the summary in and who it is for. Then produce the summary at the right length and tone.
